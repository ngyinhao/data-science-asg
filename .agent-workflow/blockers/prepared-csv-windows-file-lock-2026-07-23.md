# Prepared CSV blocked by Windows file lock

## Context and intended action

The model-training pipeline was rerun after changing the random train/test split from 80/20 to 70/30. Its first step prepares the raw Seoul Bike data and rewrites `data/processed/seoul_bike_prepared.csv`.

## Observable symptom

Pandas raised `PermissionError: [Errno 13] Permission denied` while opening the prepared CSV for writing.

On the workaround run, `joblib.dump` raised the same permission error when it tried to overwrite `models/multiple_linear_regression.pkl`. Both files have ordinary `Archive` attributes and are not marked read-only, confirming that this is not a read-only file-attribute problem.

## Impact

The normal `python src/train_models.py` workflow cannot complete while another Windows process holds generated CSV or model artifacts open. Model and evaluation artifacts are not regenerated by that command.

## Likely cause

Generated artifacts are open in another application or process with Windows locks that prevent replacement. The files remain readable.

## Troubleshooting and results

- Confirmed that preprocessing completed and the failure occurred specifically at `DataFrame.to_csv`.
- Confirmed that the existing prepared CSV remains available for reading.
- Bypassed the prepared-CSV write and confirmed that training proceeds until the first saved model is overwritten, where the same permission failure occurs.
- Confirmed that the affected files are not marked read-only.

## Workaround

Close the process using the generated artifacts, then rerun the normal training pipeline. Bypassing only the prepared-CSV write is insufficient when model files are also locked.

## Prevention

Close spreadsheet viewers or other processes using the prepared CSV before running the full pipeline. Longer term, consider writing prepared output atomically to a temporary file and replacing the destination, while retaining a model-only option that does not rewrite unchanged processed data.

## Recurrence (2026-07-27 full 70/30 refresh)

- The explicitly authorized full regeneration again failed at `prepared.to_csv(...)` with `PermissionError: [Errno 13] Permission denied` for `data/processed/seoul_bike_prepared.csv`.
- The failure occurred before model fitting or model-artifact writes, so this attempt did not partially refresh the model outputs.
- Host-level process inspection found no Excel, Python, Streamlit, editor, or BI process holding the files.
- The training and artifact scripts succeeded when rerun through the approved host-filesystem path, confirming that this recurrence was caused by the managed offline filesystem layer rather than a user application lock.
- The same layer later denied an exact three-notebook reverse patch with `unable to unlink` and `Permission denied`, while the equivalent narrowly scoped operation remained eligible for the host-filesystem workaround.
- The layer also denied deletion of a temporary PR-body Markdown file created by this workflow; cleanup succeeded only through the same explicit host-filesystem path.
